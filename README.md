# Bauer et al. (2026)

This repository contains the code used to produce the results and (most of) the figures presented in **Bauer et al. (2026)**. It is intended to allow full reproduction of the paper's analysis pipeline, from raw heliospheric imager (HI) data processing through to the final CME tracking, fitting, and forecasting results.

> **Citation**: A DOI for the paper will be added here once it is available.

## Pipeline Overview

The repository is organized as a sequence of processing stages, each living in its own folder and run in order:

| Stage | Folder | Description |
|---|---|---|
| 1 | [`HI_Data_Processing/`](HI_Data_Processing/) | Downloads and processes STEREO/HI imagery (reduction, background subtraction, running differences, J-plots). |
| 2 | [`STRUDL/`](STRUDL/) | Segments and extracts CME fronts from the processed HI data using the STRUDL segmentation model. |
| 3 | [`STRUDL_Tracking_Analysis/`](STRUDL_Tracking_Analysis/) | Downloads and matches DONKI CME data to STRUDL CME data, computes CME parameters within the ecliptic plane, generates ELEvoHI-compatible tracks. |
| 4 | [`ELEvo/`](ELEvo/) | Runs the ELEvo model. |
| 5 | [`STRUDL_Tracking_Analysis/`](STRUDL_Tracking_Analysis/) | Converts the manual CME tracks into a format compatible with ELEvoHI. |
| 6 | [`ELEvoHI/`](ELEvoHI/) | Runs the ELEvoHI model. |

The [`Tracking_Tool/`](Tracking_Tool/) folder contains an interactive HI CME tracking utility and is not part of the automated pipeline.

## Setup

This project uses [uv](https://docs.astral.sh/uv/) for Python environment and dependency management. All required package versions are pinned in [`pyproject.toml`](pyproject.toml) and locked in [`uv.lock`](uv.lock) to ensure a fully reproducible environment.

### 1. Install `uv`

If you don't already have `uv` installed, follow the [official installation instructions](https://docs.astral.sh/uv/getting-started/installation/), e.g.:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 2. Create the environment

From the root of the repository, simply run:

```bash
uv sync
```

This reads `pyproject.toml` and `uv.lock` and creates a local `.venv` with the exact package versions used to produce the paper's results (Python ≥ 3.11 is required, see [`.python-version`](.python-version)).

Any script in this repository can then be run inside the managed environment with:

```bash
uv run <script.py>
```

which automatically uses the synced `.venv` without needing to activate it manually.

## Running the Full Pipeline

The [`run_pipeline.sh`](run_pipeline.sh) script runs the entire pipeline end-to-end, executing each stage in the correct order:

```bash
run_pipeline.sh
```

Concretely, this script:

1. Runs the HI data processing pipeline (`HI_Data_Processing/main.py`)
2. Segments and extracts CME fronts using the STRUDL model (`STRUDL/extract_fronts_operational.py`)
3. Downloads the relevant DONKI data, matches STRUDL to DONKI CMEs, computes the DONKI parameters within the ecliptic plane, and converts the automatically generated tracks used for the STRUDL-ELEvoHI pipeline into a format compatible with ELEvoHI (`STRUDL_Tracking_Analysis/run_pre_fitting_pipeline.py`)
4. Runs ELEvo (`ELEvo/ELEvo.py`)
5. Converts the manually generated tracks used for the Manual-ELEvoHI pipeline into a format compatible with ELEvoHI (`STRUDL_Tracking_Analysis/fix_strudl_output.py`)
6. Runs ELEvoHI (`ELEvoHI/run_elevohi.py`)

> [!WARNING]
> **Running the full pipeline is resource-intensive.** Depending on your machine and network connection, it can take **several hours** to complete. Running the full pipeline will take significantly longer if no GPU is available for running the STRUDL model. It also requires approximately **250 GB of free disk space**, most of which is consumed by the HI data processing stage: raw STEREO/HI FITS downloads, reduced/calibrated images, running-difference images, and the J-plots generated from them. Make sure you have sufficient disk space and time available before starting a full run.

Each stage can also be run individually (in order) by `cd`-ing into the relevant folder and using `uv run <script.py>`, which is useful for re-running a single stage without repeating the entire pipeline.

## Reproducing the Figures

Once the pipeline has been run (or if you already have the necessary intermediate/output data in place), most of the figures from the paper can be reproduced by executing [`make_paper_plots.py`](make_paper_plots.py) via:

```bash
uv run make_paper_plots.py
```

Running the script will (re-)create the `paper_plots/` folder and save the generated figures there.

> [!NOTE]
> Not all figures in the paper are generated by this script — a small number were produced separately as they do not depend on the results of the pipeline.
